# Stock Research Agent

一个基于 Vue、FastAPI、SSE 和 Agno 的股票研究 Demo。包含股票分析、量化回测和新闻推送三个 Tab：输入 A 股、港股或美股代码可以分析前复权行情、验证简单策略，也可以按公司或主题检索近期新闻并由 Agent 流式梳理影响。

## 能力边界

- 支持 `600519`、`000001`、`00700`、`AAPL` 等代码。
- 沪深京 A 股统一通过 AKShare 获取行情：默认使用 `stock_zh_a_hist`，该接口不可用时回退到 AKShare 的 `stock_zh_a_daily`；完整同步同时保存前复权、不复权与后复权三套 OHLC。港股和美股暂保留东方财富兼容路径。
- 当前指标包括 MA5/20/60、RSI(14)、区间收益、年化波动率、最大回撤和成交量。
- 行情分析支持 3 个月、6 个月、1 年、2 年和 5 年范围；K 线悬浮可查看单日开高低收。
- A 股股票列表使用 AKShare `stock_info_a_code_name`；日线使用 `stock_zh_a_hist` 的 `qfq`、空字符串和 `hfq` 口径并按交易日对齐。历史遗留的腾讯、东财和 Yahoo 行不会进入新的 A 股查询或回测；AKShare 同步成功时会清除相同日期区间的旧来源行。KDJ 不是行情源直接返回，而是在本地按 `RSV(9) → K=SMA(RSV,3,1) → D=SMA(K,3,1) → J=3K-2D` 计算。K、D 初始值为 50，并使用回测开始日前最多 250 根日线预热；预热数据不计入回测收益、持仓或成交区间。
- 新闻推送聚合 Google News 与 Bing News RSS，保留来源、发布时间、摘要和原文链接，支持 24 小时、3 天、7 天和 30 天范围。
- 新闻页可在页面激活期间每 5、15 或 30 分钟自动刷新；关闭页面或切换到其他 Tab 后不会继续轮询。
- 回测可选独立的基本面评分入场过滤层，财务数据来自东方财富主要财务指标；当前仍不包含完整财报附注、历史估值和券商一致预期，Agent 被要求不得编造这些数据。
- 聚合新闻可能延迟或只有标题摘要，关键事实必须回到上市公司公告、财报和交易所披露核对。
- 输出是研究演示，不构成个性化投资建议或收益承诺。

## 配置

```bash
cp .env.example .env
```

然后只在本地 `.env` 填写：

```dotenv
OPENAI_BASE_URL=http://llmapi.bilibili.co/v1
OPENAI_MODEL=gemini-3.0-pro
OPENAI_API_KEY=
```

API Key 留空时使用本地 Demo 分析；不要把 Key 发到对话或提交到 Git。

## 启动

后端：

```bash
chmod +x start-backend.sh
./start-backend.sh
```

前端：

```bash
cd frontend
npm install
npm run dev
```

访问 <http://localhost:5173>。

## API

- `GET /api/health`
- `POST /api/analyze/stream`
- `POST /api/backtest`：支持买入持有、均线、RSI、RSI反转止盈止损、多周期趋势跟随、KDJ 急跌首阳、金叉后回踩、MA120/MA200 回踩确认等十种策略
- `POST /api/backtest/batch`：一次获取多只股票行情，批量运行多个策略并返回平均收益对比
- `POST /api/news/stream`：检索近期新闻，并以 SSE 输出原文列表和 Agent 研判
- `GET /api/market/candles`：按任意起止日期及复权模式查询本地/远程 K 线与 MA、MACD、RSI、KDJ、ATR、九转、BOLL
- `POST /api/jobs/capital-pool-backtest`：使用共享现金账户运行全市场资金池 RSI 组合回测
- `POST /api/backtests/run`：单股、多个标的或多个策略的日期范围回测，并自动保存记录
- `GET /api/backtests/records`：回测记录；结果摘要分页读取，个股曲线与 B/S 明细按需读取
- `DELETE /api/backtests/records/{run_id}`：软删除回测记录，删除后不再出现在列表及详情接口中
- `POST /api/backtests/compare`：选择 2～10 条历史记录，按记录与策略进行收益 PK
- `GET /api/factors/catalog`：读取量价、动量、低风险、质量和成长因子定义
- `POST /api/factors/analyze`：月末横截面多因子检验，返回 Rank IC、IC IR、五分组多空收益与因子相关性
- `POST /api/jobs/data-sync`：创建 A 股全市场行情同步任务，支持 `full` 全量和 `incremental` 增量模式
- `POST /api/jobs/fundamental-sync`：独立同步并缓存A股历史主要财务指标；增量模式跳过12小时内已更新的股票
- `POST /api/jobs/full-market-backtest`：基于本地数据库创建全市场回测任务
- `POST /api/jobs/market-scan`：扫描全市场最近交易日的新开仓信号
- `GET /api/jobs/{job_id}`：读取异步任务进度
- `POST /api/strategies/generate`：AI 将策略文字转换为安全 DSL
- `POST /api/strategies/explain`：AI 将策略 DSL 反向解释为文字

行情分析流式接口依次发送 `meta`、`snapshot`、多个 `token` 和 `done` 事件；新闻流式接口依次发送 `meta`、`news`、多个 `token` 和 `done` 事件；失败时发送 `error`。

“因子研究”Tab 使用 ECharts 展示 Mean IC/IC IR、月度 Rank IC、五分组多空累计收益和因子秩相关热力图。价格与成交量因子只使用调仓日及此前数据，基本面因子按财报公告生效日做历史时点匹配；每个月末对横截面进行2.5%/97.5%缩尾和标准化，复合因子暂按所选因子等权合成。多空收益是未计手续费、涨跌停和冲击成本的因子检验结果，不能直接当作可交易策略收益。

资金池新增“多因子月度轮动”：月末计算所选因子，在同日股票横截面中分别转成百分位排名，再按自定义权重合成综合分；下一月首个交易日开盘买入排名靠前的股票，并在再下个月首个交易日换仓。真实资金池继续执行总仓位、单票仓位、最大持仓、100股整数手、成交量参与率、手续费和滑点约束。因子研究页可将当前选择等权送入资金池，也可以在RSI、回踩、趋势等旧策略下把“候选排名方式”改成“多因子综合评分”：旧策略负责入场和退出时点，多因子只负责同日候选排序，避免把两套信号条件硬相与后导致长期空仓。

量化回测 Tab 支持 3 个月、6 个月、1 年、2 年和 5 年日线数据，按下一交易日开盘执行信号并扣除单边手续费及滑点；滑点默认5bps，买入成交价上浮、卖出成交价下调，覆盖个股、批量、全市场和AI DSL回测。结果包含策略收益、年化收益、持仓交易日、持仓日均复利、沪深300基准、最大回撤、夏普、交易次数、胜率和净值曲线。所有策略（包括 AI DSL）的基准统一使用相同回测首尾日期的沪深300指数 `000300.SS`，超额收益=`策略收益-沪深300收益`。单只股票年化收益按实际回测首尾自然日计算 CAGR：`(最终净值 / 初始资金)^(365.2425 / 回测自然日数) - 1`；“平均年化收益”是同一策略各有效股票年化收益的等权算术平均。持仓日均复利按 `(最终净值 / 初始资金)^(1 / 持仓交易日) - 1` 计算，未产生持仓时为空。

全市场汇总同时展示“个股夏普均值”和“组合夏普”。组合指标将所有有效股票在回测开始时等权配置，尚未上市的区间按现金净值1处理，逐日合成组合净值；组合夏普=`组合日收益均值 / 组合日收益标准差 × √252`，无风险利率按0处理。组合收益和组合最大回撤也从同一条组合净值计算，而不是对个股指标简单平均。

“启用基本面评分”是独立于交易策略的可选入场过滤层，关闭时不会改变原策略。评分满分100分，由ROE（25分）、营收同比（20分）、归母净利润同比（20分）、经营现金流/净利润（20分）和资产负债率（15分）组成，默认最低60分。历史回测按照财报公告日与更新时间中较晚者生效，信号不能使用当时尚未公开的报告；B点原因会记录实际评分，结果会记录低分过滤和缺失报告次数。行情与财报采用独立同步任务并分别持久化；全市场回测只读取本地财报缓存，不在策略计算期间访问外部接口。首次启用前应点击“全量同步历史财报”，日后使用增量同步；缓存覆盖不足80%时全市场回测会直接提示同步，不会边回测边下载。该评分是跨行业的第一版绝对评分，不等同于完整基本面研究，周期股和金融股仍需结合行业口径判断。

批量回测最多接受 30 个标的，同一标的的行情只获取一次，再运行全部策略。默认列表包含 10 只代表性 A 股，并加入沪深300（510300）、上证50（510050）、中证500（510500）、中证1000（512100）、化工（159870）、通信（515880）、创新药（159992）、半导体（512480）、科创50（588000）、白酒/酒类（512690）和证券（512880）ETF。汇总表比较平均策略收益、持仓日均复利、平均持仓日、同期沪深300收益、平均超额收益、平均回撤、平均夏普、交易次数、胜率、盈利标的比例和跑赢基准比例；单个标的失败不会中断整批。

`MA20/60首次回踩` 是仅做多策略：MA20 从下向上穿越 MA60 后开始等待，随后第一个最低价触及 MA20、且收盘价仍不低于 MA20 的交易日产生买入信号；收盘价跌破 MA60 时产生卖出信号。同一次金叉最多买入一次，信号均在下一交易日开盘成交。

`RSI反转+止盈止损` 是带波动预算的均值回归策略：RSI(14) 使用同花顺 `SMA(MAX(C-LC,0),14,1) / SMA(ABS(C-LC),14,1) × 100` 递推口径，并使用回测开始日前历史数据预热。RSI 从不高于30向上穿越30、观察日收阳，且收盘价至少高于最近20日最低价2%时产生买入信号，排除仍贴近阶段新低的弱反抽；下一交易日前复权开盘成交。初始止损距离采用信号日 `1.5×ATR(14)`，并限制在买入价的4%～5%；盈利达到8%后不立即止盈，而是启用 `2×ATR(14)` 跟踪止盈（回撤距离限制在4%～6%，且止盈线不低于买入价），以保留趋势大涨。持仓达到20个交易日且收益仍低于3%时执行时间退出；ATR初始止损后冷静5个交易日，避免连续追入同一轮弱反弹。所有退出均在收盘生成信号、下一交易日开盘成交，因此跳空时实际成交收益可能越过止损线。

独立的“资金池回测”Tab 使用共享现金账户，不再把每只股票都视为拥有一份完整本金。资金池可选择现有策略，并单独设置单日全市场RSI信号门槛、次日高开上限、最低日均成交额、股价高于MA200、MA200上升、基本面最低评分及单边基础滑点等条件；滑点默认5bps，买入价上浮、卖出价下调，成交量冲击默认关闭。基本面筛选只读取信号日当时已公开的财报，低分或缺失财报均不允许开仓，缓存覆盖不足80%时拒绝生成不完整回测。当前RSI资金池入场沿用RSI14上穿30、信号日收阳且离开20日低点2%的反转确认，退出沿用ATR初始止损、盈利8%后跟踪止盈和20日低收益退出；全市场信号数量按每日独立原始信号统计，不受影子持仓和资金池空位影响。结果保存共享资金净值、沪深300同期净值、平均仓位、最大回撤、夏普、候选/实际采用交易及逐笔成交。聚宽共享资金池版本位于 [`docs/聚宽/RSI全市场组合回测.py`](docs/聚宽/RSI全市场组合回测.py)。

`多周期趋势跟随` 是低频、仅做多的趋势策略。MA20从下向上穿越MA60只是触发器，入场还要求MA60高于MA200、MA200高于20个交易日前，个股近60日收益高于同期沪深300，并且沪深300自身收盘位于向上的MA200之上；所有条件在收盘确认，下一交易日开盘买入。持仓后不设固定止盈，MA20跌回MA60下方时在下一交易日开盘卖出，以允许盈利趋势延伸。股票与沪深300的MA200均使用回测开始日前预热数据。该版本来自2020年至2026-08-05约5270只有效A股的小范围参数对比；它显著减少熊市交易，但属于单股票信号策略，不等同于按动量排名定期调仓的横截面组合策略。

`KDJ急跌首阳T+1` 的观察条件为：观察日收盘价必须高于当日 MA200，且 J<13，最近 3 个日线间隔的 J 值平均每天下降至少 18；最近 10 个交易日呈现“红肥绿瘦”，即阳线日（收盘价高于开盘价）的平均成交量至少为阴线日（收盘价低于开盘价）平均成交量的 1.3 倍，窗口内必须同时存在阳线和阴线且成交量有效。MA200 和 J 值均使用回测开始日前的历史预热数据；J 值采用前复权 KDJ(9,3,3) 统一口径。满足条件后等待观察日之后的第一根阳线：若该阳线的 `收盘价/开盘价-1` 大于 4%，本次观察直接作废；否则在该阳线后的下一交易日前复权开盘价买入。持仓后按实际买入价计算，任一日收盘亏损达到 -3% 时止损；买入日起前 5 个交易日若未出现涨幅达到 4% 的阳线则退出；否则最多持有 20 个交易日。三类卖出条件均在收盘生成信号，并在下一交易日开盘成交。

`MA20/55金叉后J<13且涨幅<15%` 使用日线 KDJ(9,3,3)，K、D 初始值为 50。MA20 从下向上穿越 MA55 时，只有当日 MA55 高于 5 个交易日前的 MA55 才记录金叉日收盘价并开始等待；后续触发时再次要求 MA55 保持向上、MA20 仍高于 MA55、J 值小于 13，且当日收盘价相对金叉日收盘价涨幅小于 15%。同一次金叉最多买入一次；等待期间若 MA20 回到 MA55 下方则信号失效。持仓后日线收盘价跌破 MA55 视为确认跌破并产生卖出信号，均在下一交易日开盘成交。

`MA120回踩5日不破` 与 `MA200回踩5日不破` 均要求对应均线处于向上趋势：回踩当天的均线值必须高于前一交易日，价格从均线上方回踩且最低价触及对应动态均线，回踩日计为第 1 天，当天允许收盘跌破均线；第 2～5 日要求均线逐日抬升且每天最高价高于动态均线，第 5 日还必须收盘高于均线，随后产生买入信号，下一交易日开盘成交。`MA200回踩5日不破` 额外要求从回踩日到第 5 日确认期间每天均满足 MA200>MA250，否则本次信号作废。确认期间任一天均线走平、向下、最高价未过线，或第 5 日未收回均线，本次信号同样作废。持仓后任一交易日收盘跌破对应均线即产生卖出信号，下一交易日开盘成交。半年线按 MA120 计算。

同花顺 RSI反转ATR风控入场公式，以及同花顺/通达信 MA120、MA200 条件选股公式位于 [`docs/选股公式`](docs/选股公式/README.md)。RSI公式可精确复现入场筛选；依赖实际成交价和持仓状态的ATR止损、跟踪止盈、时间退出及冷静期仍由回测或交易系统管理。

回测可选择前复权、后复权、不复权和动态前复权 OHLC。动态前复权以 AKShare 后复权累计序列为正价格坐标，再除以回测末日的 `后复权收盘/不复权收盘` 比值，使末日价格回到真实价格附近；该归一化是整段序列的公共缩放，不改变 RSI、MA、KDJ、ATR 比例或收益。后复权直接使用 AKShare 累计价格；不复权保留除权缺口且不补偿现金分红，收益不等同于股东总回报。前一交易日收盘后生成信号，下一交易日所选口径开盘成交。买入成交价=`开盘价×(1+滑点)`，卖出成交价=`开盘价×(1-滑点)`；卖出日按滑点后的成交价计算隔夜收益并扣费，买入日按滑点后的成本计算日内持仓收益。无交易的持仓日按收盘到收盘计算，买入和卖出分别扣一次单边手续费。

重构后的数据、任务、回测记录和 AI 策略安全设计见 [`docs/重构架构.md`](docs/重构架构.md)。默认数据库位于 `backend/data/stock_agent.db`，可通过 `STOCK_DATABASE_PATH` 修改。

量化回测工作台支持个股即时回测和全市场异步回测。全市场模式首次选择全量同步建立 2020 年以来数据库，之后使用增量同步更新最新行情，再选择策略和复权口径一次性回测本地股票池中的全部 A 股。增量任务先用高流动性股票确定 AKShare 前复权、不复权、后复权均已齐全的安全交易日；本地三套行情已经到达该日的股票直接断点跳过，只请求仍有缺口的股票。三套接口仅末尾日期尚未同时更新时，系统保存日期交集内的完整数据并将末日留待下次补齐，不会把整只股票误判为失败。第一次使用后复权、不复权或动态前复权前必须执行一次全量行情同步，补齐不复权和后复权 OHLC。后端重启时，无法继续的旧异步任务会自动标记为失败；同一进程内也禁止重复启动行情同步。全市场回测股票池只纳入所选区间内至少有两根 AKShare 日线的股票：没有任何行情的失效代码不会制造失败，区间内曾经交易但后来退市的股票仍会保留。回测启动前会按“回测区间+400日指标预热”检查每只股票所有日线的不复权OHLC、后复权OHLC和正累计因子完整性；完整覆盖低于80%时立即提示继续全量同步。回测执行中若最终有效股票不足80%，任务也会失败并展示单股错误样例。

股票列表通过 AKShare `stock_info_a_code_name` 一次读取沪深京 A 股。若远程列表临时断连且本地已经保存过股票池，同步任务会继续使用本地股票池，并在任务状态与结果中标记降级来源；远程返回数量异常少于本地股票池 80% 时也不会覆盖本地完整列表。

AKShare K 线同步支持 1～4 个股票并发，默认使用 4；检测到大量失败后会把失败股票串行退避重试，并将后续请求自动降为 1。AKShare 首选日线接口连续失败 3 次后会熔断 5 分钟，期间直接使用备用日线接口，避免全市场逐只重复等待无效超时。完整复权模式下每只股票需分别读取前复权、不复权和后复权序列，因此第一次建立三套全量行情仍会耗时；只需要前复权回测时可选择“仅前复权”降低请求量。全量和增量同步均支持基于数据库完整度的断点续传；任务重启后会跳过已经到达安全截止日且所需字段完整的股票。名称明确带“退”或 `PT` 的股票在增量任务中保留历史数据但不再请求最新行情，也不进入接口熔断成功率。至少 20 只正常股票实际请求且串行重试后的成功率仍低于 20% 时才会熔断。

历史记录可勾选 2～10 条进行 PK。新回测记录统一展示同期沪深300基准收益及平均超额收益，并按“记录 × 策略”展开；旧记录保留其生成时的原始基准口径，不自动篡改历史结果。同一条多策略记录会产生多行，以避免不同策略的结果被混合平均。
